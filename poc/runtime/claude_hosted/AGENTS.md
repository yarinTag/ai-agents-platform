# Isolated Claude Agent SDK hosting

This module owns an opt-in **read-only repository analysis** backend for `execution_backend=claude_code`. Direct API remains unchanged; Codex/Antigravity remain pending. No SDK/package/image was installed, built or run during implementation.

## Module contracts

- `policy.py`: requires PLATFORM_ENABLE_CLAUDE_SDK=true, native Linux and digest-pinned PLATFORM_CLAUDE_SDK_IMAGE; pins SDK contract 0.2.177. Validates read-only workspace, no tool-network allowlist, workflow secrets or automatic reviewer sessions. `read_tools` intersects agent grants with Read/Glob/Grep; wildcard compatibility expands only to those three. Preflight checks current organization Anthropic key, selected model and explicit configured pricing. Frozen HostedContext binds task/execution/workflow/org/department/step/agent/credential version/deadline/model/tools/output limit. Every broker call rechecks running states, current initiator/repository/connector/department grants, workspace identity, key version and tool grants through existing governance. No inferred cross-organization context or host-auth fallback.
- `broker.py`: private AF_UNIX HTTP server outside the agent container. Accepts a random per-run capability (never a provider key) in x-api-key or Bearer auth. Only relative POST /authorize and POST /v1/messages[?beta=true] are accepted. /authorize accepts Read/Glob/Grep names within the frozen intersection. All inference goes to fixed https://api.anthropic.com/v1/messages with current organization credentials, TLS verification, trust_env=false, no redirects or transport retries. No provider response error bodies are forwarded. Rejects model substitution, output beyond agent limit (cap 32000), unsupported/server tools, multimodal/opaque document input, elevated service tiers/speed and text bodies >80000 serialized bytes. Total HTTP body cap 2 MB, response cap 16 MB, max 40 successful model calls. Standard text context and cache-write pricing are conservatively reserved; configured prices are estimates, not vendor invoice certification. Responses (including SSE) are buffered and usage reconciled before forwarding, so no live model-token streaming is promised. Provider errors/missing terminal usage stop the session; dispatched ambiguity retains reservation. Requests known not dispatched settle at zero. Failed sessions cannot retry through the broker.
- `relay.py`: network-only HTTP relay in a separate non-root container. It mounts only the private socket directory and relay source, has no application DB, provider credentials, repository or external network. Worker reaches this relay by Docker service name on its own internal network. There is no host TCP port.
- `containers.py`: one relay + one SDK worker on an internal per-run Docker network, DNS upstream disabled, capabilities dropped, no-new-privileges, read-only root, bounded /tmp tmpfs, non-root UID/GID and explicit CPU/RAM/PID limits. Worker mounts only the approved checkout **read-only** and trusted worker source. No host home/config, Docker socket, database or real provider key is mounted/passed. It receives only the scoped broker capability, fixed internal base URL and empty OAuth/auth-token overrides. Cleanup force-removes both containers and network; terminating docker's client alone is insufficient. Docker availability/image/setup failures have no host fallback.
- `worker.py`: installed SDK version must be exactly 0.2.177. Uses ClaudeAgentOptions with explicit read tools, no ambient setting sources/plugins/subagents/MCP, strict MCP config, 20 turns and no fallback model. PreToolUse checks canonical repository paths and asks the broker for current authority. PostToolUse/PostToolUseFailure emit bounded results. API retries disabled; output-token limit is also enforced at broker. Text activity is logged; thinking/signatures are not exported. Terminal SDK errors, refusals, permission denials, limit exits and non-completed terminal reasons fail. No shell, write, browser, external integrations or deployment tools. Diagnostic session IDs are tagged sdk_; ephemeral sessions cannot be resumed/forked.
- `execution.py`: integrated hosted task runner. Passes prompt/system/resolved organization skills via stdin, not files/command arguments. Emits existing system/assistant/tool_use/tool_result/usage/result events, redacts the scoped capability, checkpoints stored events at ~1s while active, limits logs to 5000 events/4 MB and lines to 65536 characters. Handles deadline/cancel/shutdown and waits for real process exit. Completion requires successful terminal result, process exit 0, at least one completed repository tool and reconciled paid calls. Unknown usage emits incomplete cost_summary and reserved_budget_usd; holds are not presented as spend. Outer runtime finalization persists the result and invokes existing lifecycle callbacks.
- `Dockerfile`: deployment template, requires a trusted Debian Python 3.12+ base-image digest. Pins claude-agent-sdk==0.2.177 and installs ripgrep/CA certificates. Resulting deployment image must also be pinned by digest. Transitive package locking, image scanning and build verification remain deployment acceptance work; no build has been run.

## Accounting and persistence

`storage/hosted_budget.py` owns hosted_model_requests. Its fields are id, organization_id, department_id, execution_id, task_id, model, reserved_micros, charged_micros, state (RESERVED/SETTLED/UNKNOWN), pricing_json, usage_json, created_at; organization/department FKs cascade. Reservations use BEGIN IMMEDIATE and integer micro-USD. Known configured-rate estimates are included in department spend without duplicating finalized workflow aggregates; RESERVED/UNKNOWN are separate `reserved_usd` in budget checks. Crash/ambiguous reservations never auto-expire and require audited operator reconciliation before release. No reconciliation API is added here. This does not retrofit atomic per-call reservations into existing Direct API workers; already-running legacy calls remain a cross-backend concurrency limitation.

## Verification boundary

No tests, imports/SDK execution, lint/typecheck/build, Docker, startup, paid calls or messages were performed. Test source: poc/tests/test_claude_hosted.py (real SQLite and private Unix HTTP transport, policy denial, grants/keys/cancellation, concurrent reservations, unknown charges, SSE parsing). Container/network behavior, SDK wire compatibility, rate bounds, complete cancellation, UI rendering and live Anthropic success are **not verified**. Feature is disabled by default. See docs/claude-hosted.md for deployment requirements and deferred acceptance gates.

Hosted final answers additionally use the existing direct_outcomes completed/blocked envelope. Missing/blocked outcomes are FAILED, never completed clarifications; a fresh execution is required after resolving input because resume is unsupported. The host rewrites the persisted result event accordingly before publication.

Workflow mid-run budget checks subtract this execution’s already-accounted settled hosted usage from the incremental workflow total, avoiding charging the same in-flight SDK usage twice before final aggregate rollup.
