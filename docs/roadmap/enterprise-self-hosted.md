# Enterprise Self-Hosted על Kubernetes

## יעד המוצר

לספק חבילת התקנה שהלקוח יכול להפעיל ולשדרג בתוך אשכול Kubernetes בבעלותו, בענן פרטי או באתר מקומי. הארגון מפעיל בתוך הגבול שהגדיר את ה־API, ה־UI, ה־workers, סביבות הסוכנים, האחסון, שירותי הזהות, מקורות הקוד והנתונים ושירותי ההסקה. קוד, סודות, prompts, תשובות מודל, תוצרים ולוגים נשארים בגבול הזה.

**מבחן המוצר:** אשכול שאינו מחובר לאינטרנט מסוגל לעבור התקנה נקייה, להריץ משימת סוכן על ריפו פנימי באמצעות מודל פנימי, להפיק תוצר מאושר, לשדרג ולשחזר מגיבוי. אין תלות בשירות רישוי, control plane, טלמטריה, inference או registry של ספק מחוץ לרשת.

## החלטות ארכיטקטוניות מוצעות

- **בסיס אחיד לכל הפריסות.** אותה חבילת Kubernetes ל־EKS, GKE, AKS ואשכול מקומי, עם ערכי התקנה ופרופילי תאימות נפרדים. לפריסה מחוברת אפשר לייבא חבילות ממקור מאושר. לפריסת air-gap הייבוא מתבצע במסירה אופליין של חבילה חתומה. מסלולי המשימה עצמם משתמשים בשירותים פנימיים בשני המצבים.
- **גבול המידע כולל יעד בפועל.** כתובת פרטית או Private Endpoint אינם מספיקים כשספק חיצוני עדיין מעבד את הנתונים. ספק inference מתאים לפרופיל הסגור רק כשההסקה עצמה רצה בגבול הלקוח, והלקוח שולט במסלולי האחסון, הלוגים והטלמטריה. אותו עיקרון חל על Git, אחסון תוצרים, זהות ורישוי.
- **הפרדה בין מישור הבקרה למישור הביצוע.** ה־API שומר תכנית הרצה לניסיון. מנהל הסביבות יוצר Kubernetes Job לכל ניסיון סוכן, מכין checkout וקלט מורשה, ומצמיד לו זהות קצרה. הסוכן ניגש למודל ולנתונים דרך שירותי תיווך פנימיים. פעולות חיצוניות, למשל פתיחת PR ב־Git פנימי, מתבצעות בשירות ייעודי עם בדיקת הרשאה וקבלה.
- **בידוד שכבות.** תשתית הלקוח מגדירה את גבול הרשת. מדיניות אשכול סוגרת יציאות ומגבילה גישה בין רכיבים. כל Job מקבל קבצים, משאבים וזהות של הניסיון שלו. מדיניות רשת וזהות נאכפת גם על רכיבים תומכים, כולל גיבוי, ניטור ושירות המודלים.
- **מנועים הם שילובי תאימות.** כל שילוב של מנוע, מודל, גרסה וסוג פריסה נבדק בנפרד. אם Claude Code, Cursor או Codex מחייבים חשבון, inference, רישוי או תעבורה מחוץ לגבול הלקוח, הם אינם זמינים בפרופיל הסגור. תמיכה בשם מנוע אינה התחייבות לתמיכה אופליין.

## פערים מול המאגר

- קיימת תצורת Docker Compose עם Docker socket ל־worker. חסרים חבילת Kubernetes, מנהל Jobs וחבילת ייבוא אופליין. [Compose](../../docker-compose.enterprise.yml)
- סביבת הריפו מבודדת את כלי Direct API ב־Docker, בעוד שתהליך ה־worker נשאר בצד השרת. מסלול Claude SDK הקיים הוא לקריאה בלבד ומתווך אל Anthropic, ולכן הוא אינו עומד כפי שהוא בדרישת inference פנימי. [סביבת ריפו](../repo-workspaces.md) · [אירוח Claude](../claude-hosted.md)
- מסלול הריפו מאשר GitHub ומשתמש בתשתית checkout ומטמון קיימת. נדרשת תמיכה בשרת Git פנימי ובגישה ל־registry, אחסון, זהות ומפתחות בתוך גבול הלקוח. בחירת מסד הייצור דורשת אימות מול צורת ההתמדה בפועל. עצם קיומו של שירות PostgreSQL ב־Compose אינו ראיה שכל הרכיבים תומכים בו. [הרשאות ריפו](../../poc/integrations/repo_workspace.py)
- ביטול וניקוי קיימים ברמת השלב, אך חסרים התאוששות וניקוי מאומת לאחר אובדן worker. מנועי סוכן נוספים דורשים אימות ממשק והרשאות ולא רק רישום במערכת. [ניקוי](../../poc/integrations/repo_workspace.py) · [מנועי הרצה](../execution-backends.md)

## טיקטים

### ENT-01 — מודל פריסה, גבול נתונים ומטריצת תאימות
- **תלות:** אין.
- **תכולה:** למפות את מסלולי הרשת, הנתונים והזהות של API, workers, Git, מודלים, registry, רישוי, לוגים, גיבויים, תמיכה ושירותי זמן ו־DNS. להגדיר מה שייך לגבול הלקוח, מי מפעיל כל שירות ואילו גרסאות Kubernetes ושירותי תלות מאושרים בכל פרופיל. להגדיר מטריצת אחריות בין הלקוח לספק וחוזה קבלה ל־air-gap.
- **קבלה:** לכל חיבור ידועים מקור, יעד, סוג מידע, בעלים ודרך אכיפה. מסלול שהיעד שלו מחוץ לגבול חוסם אישור פרופיל סגור. קיימת סביבת יעד מקומית אחת לפיילוט ותכנית אימות נפרדת ל־EKS, GKE ו־AKS.

### ENT-02 — חבילת התקנת Kubernetes
- **תלות:** ENT-01.
- **תכולה:** להכין chart עם API, UI, תור, workers, מנהל סביבות ושירותי תיווך. להגדיר ערכים לשירותים פנימיים קיימים, ingress פרטי, CA ארגוני, DNS פנימי, אחסון מתמשך, probes וחשבונות שירות. להכריע ולבדוק את מסד הייצור, מנגנון המיגרציות ופרופיל הזמינות. לקבוע אילו רכיבים מגיעים בחבילה ואילו הלקוח מספק.
- **קבלה:** התקנה נקייה מקימה את הרכיבים מול שירותים פנימיים בסביבת בדיקה. ENT-04 מאמת שההתקנה פועלת גם תחת מדיניות הרשת הסגורה. הפעלה מחדש משמרת נתוני משימה. הגדרה חסרה או גרסת מסד לא תואמת נחשפות לפני קבלת עבודה. אף רכיב מוצר אינו דורש Docker socket באשכול.

### ENT-03 — אספקה אופליין ואימות שרשרת אספקה
- **תלות:** ENT-01, ENT-02.
- **תכולה:** לארוז chart, images לפי digest, חתימות, SBOM, כלי ייבוא ו־manifest גרסאות. לתעד העברה וייבוא ל־registry פנימי, אימות חתימות ללא גישה לאינטרנט ועדכון חבילות. לכלול תלות במודלים ובמשקולות שאושרו בארגון, לפי תנאי ההפצה, או להגדיר ממשק לשרת הסקה שהלקוח מספק.
- **קבלה:** התקנה באשכול נקי עם registry פנימי בלבד עובדת מהחבילה המתועדת. רכיב חסר או חתימה לא תקינה עוצרים התקנה. גרסה חדשה ניתנת לייבוא ואימות באותה שיטה.

### ENT-04 — רשת סגורה, זהות ארגונית ומפתחות
- **תלות:** ENT-01, ENT-02.
- **תכולה:** להגדיר ingress פרטי, ברירת מחדל חוסמת egress והרשאות רשת ורכיבים לפי צורך. לחבר ספק זהות פנימי, TLS ו־CA ארגוני ו־Vault או שירות מקומי מקביל. לבטל קריאות חיצוניות מובנות, כולל telemetry, בדיקות עדכון ורישוי מקוון. אם נדרש רישוי Enterprise, להגדיר רישיון ניתן לאימות אופליין.
- **קבלה:** לקוח ללא אינטרנט יכול להתחבר ולהפעיל משימה. בדיקות תעבורה מאמתות שרק יעדים פנימיים מאושרים נגישים, גם בעת שגיאה. רוטציה ושלילה של מפתח פועלות מתוך הרשת. אין ערכי סודות בחבילת ההתקנה או בלוגים.

### ENT-05 — מודל פנימי ושירות תיווך
- **תלות:** ENT-01, ENT-04.
- **תכולה:** להוסיף חיבור מנוהל לשירות inference פנימי עם קטלוג מודלים מאושרים, TLS, זהות, תקציב ומדידת שימוש. לאפשר חיבור רק ליעדים שנקבעו מראש בידי מפעיל הפריסה. לחבר את Direct API למסלול זה ולמפות פלט, כלי מודל והגבלות לכל משפחת מודלים שנבחרה לפיילוט.
- **קבלה:** בקשת מודל, תשובה וקריאות המשך מתבצעות מול שירות פנימי בלבד. כשל מודל או חוסר תאימות מדווחים למשימה. אין מעבר אוטומטי לספק חיצוני. הוכחת קבלה כוללת משימה עם מודל שהלקוח מפעיל בפועל.

### ENT-06 — Sandbox ייעודי לכל ניסיון סוכן
- **תלות:** ENT-02, ENT-04.
- **תכולה:** להגדיר תכנית הרצה עם tenant, סוכן, מזהה ניסיון, מנוע, גרסת image, מקורות מורשים, deadline ומגבלות משאבים. ליישם Kubernetes Job לכל ניסיון עם ServiceAccount מוגבל, מדיניות Pod, נפח זמני, וחיבורי רשת מפורשים. לשמור ניהול בעלות, ביטול, התאוששות וניקוי מאומת בנפרד מתוצאת המשימה. להעביר את תהליך Direct API עצמו לתוך ה־Job.
- **קבלה:** משימה ישירה ושלב Workflow משתמשים באותו חוזה. שני ניסיונות אינם חולקים נתיב, זהות או volume. ביטול, timeout, אובדן Node וקריסת מנהל הסביבות עוברים בדיקות. ניסיון חוזר מקבל סביבה חדשה, וניקוי נכשל מופיע לתפעול ונעשה שוב.

### ENT-07 — Git ונתונים פנימיים עם גישה מוגבלת בזמן
- **תלות:** ENT-04, ENT-06.
- **תכולה:** להוסיף מתאם ראשון לשרת Git פנימי ולמקור תוצרים פנימי. הכנה תפתור commit וגרסת קלט, תאשר משאב לפי זהות ותקפיא provenance. שירות תיווך יספק גישה קצרת־חיים לניסיון. כשמקור נתונים אינו יכול להנפיק אסימון קצר, הסוד הקבוע נשאר בשירות התיווך. כתיבה ופתיחת PR יעברו דרך פעולה מבוקרת ותוצאה מתועדת.
- **קבלה:** גישה בין ארגונים, לניסיון אחר, לאחר תפוגה או לאחר שלילה נדחית. checkout עובד בלי Git ציבורי. פרופיל קריאה בלבד נאכף בסביבה. ניסיון חוזר אחרי פרסום חלקי אינו יוצר PR כפול.

### ENT-08 — תאימות מנועי סוכן
- **תלות:** בדיקת היתכנות יכולה להתחיל אחרי ENT-01. פיתוח מתאם ואימות מקצה לקצה תלויים ב־ENT-05, ENT-06 ו־ENT-07.
- **תכולה:** להוציא תתי־טיקטים נפרדים ל־Claude Code, Codex, Cursor וסוכנים מותאמים. לכל מנוע לתעד דרישות רישוי ואימות, inference נתמך, תלות רשת, היכולת להפעילו ב־Job של הלקוח, גרסה, פורמט אירועים, כלי קבצים ו־Shell, וביטול. למנוע מותאם להגדיר manifest, אישור image וחוזה קלט ופלט. להתחיל בשער היתכנות לכל מנוע חיצוני לפני התחייבות לפיתוח מתאם.
- **קבלה:** מנוע מאושר מדגים הרצה כשהאינטרנט חסום, עם קוד ומודל פנימיים. שילוב שלא עבר קבלה מסומן כחסר תמיכה בפרופיל הסגור עם הסיבה. הפעלה אינה מחייבת חשבון אישי של מפעיל.

#### ENT-08A — Claude Code
להעריך האם גרסת ה־SDK יכולה לפעול מול שירות inference פנימי מאושר. המימוש הקיים משתמש ביעד Anthropic קבוע. קבלה מחייבת ניתוח ריפו פנימי בהיעדר גישה ליעדי Anthropic חיצוניים, או תיעוד שהשילוב אינו אפשרי עם הגרסה והאימות שנבדקו. תמיכה בכתיבה תיבחן לאחר קבלת מסלול הקריאה.

#### ENT-08B — Codex
לאמת ממשק אוטומציה, מודל פנימי תואם ודרך אימות שאינה תלויה בשירות חיצוני. אם נמצא שילוב נתמך, למפות אירועי תהליך ותוצאת שינוי לתוצאה המשותפת. קבלה כוללת הרצה לא אינטראקטיבית, ביטול וקליטת תוצר בתוך האשכול.

#### ENT-08C — Cursor
לאמת אם קיים ממשק נתמך שמפעיל את הסוכן ב־Job בבעלות הלקוח, כולל אימות, רישוי והסקה מקומית. אם התנאים מתקיימים, להגדיר מתאם ולהוכיח את גבול התעבורה. אחרת לסגור את בדיקת ההיתכנות עם הסיבה ולהשאיר את המנוע לא זמין בפרופיל הסגור.

#### ENT-08D — סוכן מותאם
להגדיר manifest עם גרסת פרוטוקול, image פנימי לפי digest, קלט, פלט ויכולות מבוקשות. לאשר images לפי מדיניות הלקוח לפני קבלה. קבלה כוללת הרצת image לדוגמה והוכחה שרישום image אינו מקנה גישה למקורות מידע, סודות, רשת או פעולות מעבר למדיניות הניסיון.

### ENT-09 — תפעול מקומי, שדרוג ושחזור
- **תלות:** ENT-02 עד ENT-07.
- **תכולה:** להוסיף ניטור ולוגים מקומיים, audit, מדיניות שמירה, גיבוי ושחזור של נתונים וסודות, כלי בדיקת תקינות וראיות למצב הקצאה וניקוי. להגדיר שדרוג ומיגרציות, תאימות מול גרסה קודמת ומסלול התאוששות מכשל שדרוג. אם מועברת חבילת תמיכה, הלקוח מפיק ומאשר אותה מתוך הסביבה.
- **קבלה:** מפעיל משחזר פריסה מגיבוי פנימי ומאמת שלמות נתונים והרשאות. שדרוג מתבצע מחבילה מקומית ומסלול התאוששות נבדק. דוח תפעולי מציג ריצות כושלות, Jobs יתומים ופעולות מנהל מקומיות.

### ENT-10 — שער שחרור Enterprise
- **תלות:** ENT-01 עד ENT-07 ו־ENT-09. מנועים מעבר ל־Direct API מותנים ב־ENT-08.
- **תכולה:** להפעיל בדיקת קצה־לקצה בפריסת air-gap אמיתית, ולאחר מכן לאמת פרופילי ענן פרטי מול מטריצת תאימות. למדוד זמני הקמת Jobs וקיבולת, ולבדוק כשלי תשתית, שלילת הרשאות, בידוד בין משימות ותעבורה. להפיק מדריך התקנה ותפעול וראיות לשימוש בביקורת לקוח.
- **קבלה:** התקנה נקייה, התחברות, checkout, inference, תוצר, ביטול, ניקוי, שדרוג ושחזור מוכחים בפרופיל שנבדק. תצפית רשת מתעדת שאין יציאה מגבול הלקוח. ההצהרה למכירות ולתפעול כוללת רק גרסאות, פריסות ומנועים שנבדקו. התאמה לרגולציה נבחנת אצל כל לקוח לפי בקרותיו.

## סדר מסירה מוצע

1. **חבילת בסיס סגורה:** ENT-01 עד ENT-04. להוכיח התקנה אופליין וזהות ארגונית.
2. **הרצת עבודה מלאה:** ENT-05 עד ENT-07. להוכיח משימת Direct API על Git ומודל פנימיים ב־Job מבודד.
3. **הפעלה ארגונית:** ENT-09 ו־ENT-10. להוכיח תפעול ושדרוג בתצורה מנותקת, ואז להרחיב לפרופילי ענן לפי תוצאות.
4. **מנועים נוספים:** ENT-08. להתחיל בדיקות היתכנות במקביל, ולהוסיף שילובים מאומתים תוך שמירה על גבול הנתונים.
